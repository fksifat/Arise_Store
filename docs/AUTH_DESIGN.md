# Account form design and remembered sessions

Login and registration share `AuthFrame`, `AuthField` and `PasswordField` in `src/components/auth/AuthUI.tsx`. The shared controls use normal flex layout for icons and reveal buttons, labelled inputs, visible focus, keyboard-accessible password toggles and consistent 46px input surfaces. Registration keeps name, email, password and confirmation, with dot placeholders for both password fields. A required unchecked policy agreement sits above Create account; the existing Sign in link follows the button. Registration policy links are in the agreement instead of a duplicate footer. The checkbox provides browser form validation; no server consent record is stored. The account-first website setup flow is unchanged.

Login keeps email/password and adds an unchecked **Remember me for 7 days** option. The API accepts optional `remember_me` on `/api/v1/auth/login`; omission/false preserves the configured normal session period. True creates a seven-day access token and a cookie with `Max-Age=604800`. Both use the existing HTTP-only, SameSite and production Secure-cookie settings. Logout still revokes the token through the existing Redis/development revocation mechanism; a remembered session does not bypass revocation or account deactivation. Registration uses the normal configured session duration.

Demo credential buttons remain development-only and appear below the primary form. They clear remembered login and fill sample credentials; they do not submit the form automatically. The owner requested UI only for password recovery: a disabled Forgot password? button appears beside Remember me. The private-device helper and Coming soon labels were removed at the owner’s request. This release does not provide a recovery/email delivery service. The account switch reads Don't have an account? Create an account.

Privacy and terms links open `/privacy` and `/terms` in a separate tab to preserve account-form input. The owner explicitly requested draft content. Both routes visibly state that they are drafts and are marked noindex. Their content describes verified product behavior and flags missing operating-entity, policy-contact, retention, deletion and final contract details. They do not claim regulatory compliance and are not approved legal policies. Owner/legal review is required before publication as final terms or a privacy notice.

## Supplied AriseSell references

The latest visual pass follows the user-supplied screenshots: a Back to Home capsule above a compact 400px card, centered in-card Arise branding and headings, 26px desktop horizontal padding, 46px input surfaces, softer borders, green actions and a pale green page backdrop. The owner subsequently requested a smaller layout: 26px headings, 8px field gaps and 14px input text. Mobile uses 22px/18px horizontal panel padding at narrower breakpoints. Existing four-field registration and functional demo/session behavior remain intact. At the owner's request, both forms include a disabled Google button above an email divider; Google authentication is not connected. Password recovery and a server consent record are not implemented; linked policies remain drafts.

Registration requires 8–128 password characters on the form and API. There is no permanent minimum-length hint. A non-empty password shows a strength bar and Weak/Fair/Good/Strong label based on length and character variety; clearing it hides the feedback. This is visual guidance, not an additional acceptance rule. The administrator CLI retains its separate 12-character minimum.

The vertical layout uses 10px page padding (12px on mobile), 12px panel top/bottom padding, smaller brand/header/divider margins and an 8px field gap. Inputs retain 46px surfaces and reveal buttons retain 44px targets. On shorter screens the page can still scroll rather than clip form controls.

Login and registration now share the same 16px logo-to-heading margin, panel padding and 10px spacing between input fields. The login options row uses a compact 32px height like the registration agreement row.
